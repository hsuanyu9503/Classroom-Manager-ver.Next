## 2. 設計 Tokens

W1 的 CSS 一律使用以下語意 token，**集中在一個檔案中定義**；正式色票決定之後，只改這個檔案。

| Token | 用途 | 暫定值（**不是**正式決策） |
|---|---|---|
| `--color-primary` | 主要按鈕、連結 | `#2D5F76`（上游範本的示範預設） |
| `--color-bg` | 頁面背景 | `#F7F8FA`（同上） |
| `--color-text` | 主要文字 | `#19232A`（同上） |
| `--radius` | 卡片與操作元件 | `14px`（同上） |
| `--color-surface`、`--color-muted`、`--color-line` | 卡片、次要文字、分隔線 | 待定 |
| `--color-status-done`／`-conflict`／`-unknown`／`-denied` | 送出狀態（§4） | 待定 |

- 暫定值只用於開發期間的畫面，截圖一律標示「暫定色票」。
- 不論顏色如何決定，§1 的準則都要成立，尤其是「狀態不只用顏色表示」。

## 3. 排版與響應式

- 三個範圍（§1）：手機 360～599px、平板 600～1023px、桌面 1024px 以上。
- 驗收時的截圖寬度：
  - 手機 390 × 844；
  - 平板 1024 × 768，對應課堂中 iPad 橫向的使用情境；
  - 桌面 1440 × 900。
- 任何寬度都**沒有水平捲動**；長名稱與長代碼自動換行。
- P1 名冊：桌面與平板用表格；手機改成一欄的卡片清單，每張卡片顯示座號與狀態。

## 4. 主要頁面與狀態

| 頁面 | 重點 |
|---|---|
| 頁首 | 網站名稱；**測試情境標示**（例如「測試情境：S-LEAVE-SC01｜虛構資料」），永遠可見、不能關閉（SPEC §3） |
| P1 名冊與點名摘要 | 摘要：P／R／N／U、合計、已到、已登記；名冊：座號、狀態 |
| P2 請假摘要 | 假別、時段（上午／全天）、版本；不顯示「請假適用」 |
| P3 請假更正 | 確認對話框：說明「上午 → 全天」與目前版本；送出中的狀態 |
| P4 結果確認 | 見下表 |

**送出結果的呈現**（SPEC §4）：

| 狀態 | 文字（草案） | 文字以外的標示 | 動作 |
|---|---|---|---|
| 已完成 | 「已更正為全天（版本 N）。收據：…」 | 「完成」標籤 | 關閉 |
| 衝突 | 「資料已被其他裝置更新，請確認最新內容後再決定是否更正。」 | 「衝突」標籤 | 重新讀取 |
| 結果尚未確認 | 「送出結果尚未確認。修改可能已經完成，也可能沒有完成。」 | 「尚未確認」標籤，持續顯示 | 查詢結果、重新送出同一操作 |
| 結果尚未確認，目前無法存取 | 「先前的送出結果尚未確認，目前無法存取。」 | 「尚未確認」標籤 | 無（開發情境中需要重新啟動） |
| 無法存取 | 「無法存取。」（沒有權限與資料不存在相同） | 「無法存取」標籤 | 無 |

- 「結果尚未確認」**不得**使用與「已完成」相同的標示，也不得使用「已完成」「未修改」之類的字眼。
- 每個狀態都有文字標籤；顏色只是輔助。

## 5. 互動與無障礙

**準則**（§1）：鍵盤可以完成全程操作、焦點看得見、元件有文字標籤、尊重 `prefers-reduced-motion`。

**從既有網站參考的功能性作法**（只參考行為，不參考外觀）：
- 對話框：Escape 或「返回」可以關閉，關閉後焦點回到原本的按鈕；對話框內 Tab 焦點循環。
- 減少動畫時，不使用位移或翻轉動畫。
- 資料安全的提示：既有網站在「多分頁同時修改」時，會停止寫入、持續顯示警示，並提供「重新載入最新資料」。W1 的「衝突」與「結果尚未確認」沿用同樣的原則：
  - 持續顯示，不自動消失；
  - 說清楚目前**不知道**什麼；
  - 只提供安全的下一步。
  - W1 **沒有**「下載本頁資料備份」，因為頁面不保存資料。

**W1 另外的規定**：
- 送出中的按鈕停用，並有文字標示；狀態變化以 `aria-live="polite"` 宣告。
- **關閉對話框不等於放棄操作**：P3／P4 的對話框可以用 Escape 或「返回」關閉，但「結果尚未確認」的凍結操作仍然保留，頁面持續顯示「尚未確認」，並可以再次開啟 P4（SPEC §4）。停止整個開發情境是另一件事，屬於啟動器的責任（SPEC §3）。
- 觸控元件至少 44 × 44 px。

## 6. 從既有網站參考的功能（只限功能）

| 既有網站的功能 | W1 的處理 |
|---|---|
| 學生頁的「學生出缺席登記」（依日期登記、查看出缺席紀錄） | P1 以同樣的「選一個日期，看全班狀態」方式呈現；W1 只讀，不登記 |
| 請假「連動前一個實際上課日的作業」 | **不沿用**：W1 的資料模型規定請假不得自動改寫點名（SPEC §2.3） |
| 多分頁覆寫保護 | 只沿用原則（§5）；W1 的衝突由受控 API 的版本檢查判定（SPEC §4） |
| 作業、聯絡簿、成績、座位等 | 不在 W1 |

基準是 `Homework-manager-` `cdaf91e`（SPEC §8，Q-1 已決定）；只參考功能。
